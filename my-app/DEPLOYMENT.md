# WYD 배포 준비

웹앱은 서버 번역 API가 있어 정적 내보내기만으로 운영할 수 없습니다. Next.js 서버 또는 검증된 Worker 빌드가 필요합니다. Android는 HTTPS 서버에 연결하며 DB·번역 모델을 APK에 포함하지 않습니다.

1. [이전 계획](../docs/SUPABASE_ROLLOUT.md)에 따라 기존 Supabase를 읽기 전용으로 조사하고 백업 복구를 검사합니다. 새 스테이징에서 인증·권한을 확인합니다.
2. 기존 호스팅·도메인을 조사하고 없으면 요금제와 안정적인 HTTPS 주소를 확정합니다. 공개 배포·유료 계약·운영 보안 변경은 소유자 승인 후 진행합니다.
3. NEXT_PUBLIC_SUPABASE_URL과 NEXT_PUBLIC_SUPABASE_ANON_KEY를 빌드 환경에 설정합니다. 선택적인 MYMEMORY_EMAIL은 서버 전용입니다. 비밀키·서명키·.env.local은 공개 저장소에 넣지 않습니다.
4. 고정 커밋을 스테이징에서 검사하고 실제 두 기기의 전체 행사 흐름을 확인합니다.
5. 승인된 스키마 이전·서버 전환 후 동일 도메인에서 QR·앱·브라우저를 확인합니다.
6. 영구 관리 테스트 서명과 검증된 HTTPS 주소로 Android를 배포하고 Galaxy Tab 검사 후 정식 배포를 준비합니다.

/api/health는 프로세스 응답과 설정 존재만 검사합니다. 설정이 없으면 503, 있으면 200과 dependencies: not_probed를 반환하며 DB 정상 상태를 보증하지 않습니다. 비공개 미설정 검토본의 503은 예상된 준비 상태입니다.

GitHub CI는 검증용입니다. 푸시가 운영 서버·DB를 자동 변경하지 않습니다. 운영 계정·환경 변수·도메인·오류 알림을 아직 설정하지 않았습니다. [비용·로그·복구 계획](../docs/OPERATIONS.md)을 참고하세요.
